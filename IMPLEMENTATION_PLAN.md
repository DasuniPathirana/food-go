# Game transformation implementation plan

17 November 2026. Work proceeds in validated vertical slices. This is not a statement that all slices have shipped.

Delivery update on 18 November: [Milestone 23](docs/progress/23-game-map-foundation.md) implements Slice 1. [Milestone 24](docs/progress/24-camera-and-discovery.md) adds fixed-eye touch/keyboard/optical look, explicit device compass, loaded-building camera clearance, a guarded GLB admission/animation path and coarse geographic discovery with opt-in private persistence. [Milestone 25](docs/progress/25-restaurant-encounters.md) adds approved restaurant pools, private inventory, one-use staff confirmation and redemption, independent review and an original SVG/CSS chest. Encounters remain disabled by default; genuine partner pools, signed-in deployed journeys and competing-transaction acceptance are still required. Premium world-avatar art/shared map rendering, native AR and physical-device acceptance remain incomplete. Browser observations remain unverified and never award progression.

1. **Geographic viewport, HUD and location.** Retain MapLibre and Leaflet; no engine migration/dependency install. Expand the scene to the space below the brand/search and above navigation. Move layers to a compact contextual control, keep meaningful camera choices within thumb reach, remove duplicated locate controls. Add a static-art character button with tap/hold/drag/keyboard semantics. Keep details, walking and customisation below the scene. Stabilise cosmetic GPS independently of raw accuracy. Validate unit, interaction, responsive, fallback, types/build/security checks and actual screenshots.
2. **World avatar.** Keep procedural art as a documented proxy. Add an asset contract/loader and animation controller when licensed rigged assets pass the budget and clip checks in ASSET_REQUIREMENTS. Integrate with the map shared GL context rather than allocating a renderer per world entity. Verify ground scale, heading, interpolation and disposal before claiming premium art complete.
3. **Unified cameras.** Evolve the existing geographic calculator to overhead, follow, close and eye profiles. Preserve user zoom and detached browsing; use continuous reduced-motion-aware transitions. Implement device orientation only behind an explicit permission action. No collision-aware claim without geometry queries and tests.
4. **Spatial discovery.** Shared bounded spatial-cell contract and tests, authenticated per-user persistence, server movement acceptance and retention, then map reveal and offline retry. Establish verification limits first. Separate local preview from persistent discovery and any reward eligibility.
5. **Encounters / inventory.** The checked schema/RPCs and browser presentation are implemented behind `FOOD_GO_ENCOUNTERS_ENABLED=false`. An independent operator approves each immutable pool; purpose-bound hashed one-use staff codes, stock locks, idempotency, expiry and saved cooldowns govern private inventory. Public venue hints and exact-shop details stay below the geographic scene. Complete genuine partner content, deployed customer/staff journeys and actual competing-transaction acceptance before enabling. The illustrated chest is original SVG/CSS; richer 3D assets remain separate work. No hosted reset or fictional reward seed.
6. **Camera / native AR.** Implement a capability-based session boundary. Native ARKit/ARCore tracking requires native development builds, permission/store changes and physical devices. Browser support must report its actual tracking level. Denied/unsupported fallback remains a normal verified-code encounter, without fabricated AR.
7. **Progression / optimisation / release.** Reuse existing server XP and campaign ledger; connect validated spatial milestones and inventory. Measure renderer frame times, resources, context recovery, network/GPS interruption and battery behaviour on named devices. Preserve catalogue/community/partner regressions. Deployer completes documented account/provider gates separately.

For each slice: inspect, state decision, implement, focused tests, workspace checks, production build, browser captures and fix observed defects. Record limitations precisely in progress notes. Native acceptance is separate from browser emulation. No new major dependency until compatibility, licence, byte cost and maintenance are evaluated. Existing pinned MapLibre/Three/Leaflet already cover Slice 1.
