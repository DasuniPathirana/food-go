# Camera controls and geographic discovery

17 November 2026. Continues the requested game transformation on the existing geographic renderer. This delivers camera/input and coarse discovery foundations, not the complete premium character, encounter or native AR programme.

## Delivered behaviour

Street view keeps the camera at the explorer's actual geographic position plus 1.7 metres. Drag and arrow keys rotate its look; two-finger pinch, wheel and the map zoom buttons change optical field of view rather than moving the eye. Home resets look and Face north resets yaw. A street tap still selects once and requests one route. Returning to Overview restores normal map gesture handlers. Detached browsing remains available.

Device compass is optional and starts only from its explicit camera-menu action. Supported browsers request orientation permission from that gesture. Only usable absolute heading samples are accepted, with a signal timeout, throttling and visible denied/unavailable states. Touch/keyboard look yields continuously from the last sensor direction and stops sensor control. Leaving Street view, hiding Explore and unmounting stop listeners. Permissions Policy enables same-origin motion sensors; camera and microphone remain disabled. Browser emulation proves event handling, not real hardware orientation accuracy.

Follow and close cameras now query loaded geographic building footprints and vertical extents. A bounded segment/volume calculation shortens an obstructed boom without moving the explorer. A blocked target or almost-zero boom raises the camera to Overview and explains why. Courtyards, holes, low walls, overhangs, roof heights, dateline geometry and geometry arriving after initial load have checks. Queries apply a 75-metre footprint-distance filter before the feature cap, cache nearby geometry for 500 ms, cap feature/vertex work and use the same Game height transform as the visible building layer. Actual rendering exposed a local survey returning more than 20,000 shapes; limiting the list before locality filtering could miss a nearby wall. The browser regression supplies 3000 distant loaded footprints before a blocking wall, with deliberately distant-first source ordering, to exercise this case. Unloaded/incomplete tiles, arbitrary terrain, interiors, transparent windows and full player physics are outside this mechanism. It is camera clearance against available volumes, not a collision-free world guarantee.

The GLB asset admission path now checks local canonical paths, exact bytes and SHA-256, commercial/redistribution licence metadata, height/eye/ground metrics, forward axis, in-place root policy, walk/jog cycle distance and nine distinct clip names. The loader bounds downloads and parse resources, rejects external resources and unsupported compression, validates a skinned rig and geometry/material/texture budgets, drives an actual AnimationMixer with crossfades and one-shot actions, and disposes resources across failure/abort/teardown. It is integrated into the current avatar renderer with procedural fallback and reduced/hidden-motion behaviour. The production catalogue is deliberately empty. An authored embedded test rig demonstrates actual parsing and animation only; no premium production character art or shared map-GL world avatar has been delivered.

## Geographic fog and privacy

Discovery uses canonical `wm18:x:y` Web Mercator cells in the shared domain package. A cell is about 121 metres wide in Melbourne; its geographic dimensions vary with latitude. The shared geometry rejects points beyond the Mercator domain rather than relocating them, handles the dateline and wraps world copies, and bounds each reveal to 25 nearby cells. GPS uncertainty reduces visual reach. Fog consists of actual unexplored geographic rectangles with gaps where cells are explored, not a screen-space gradient. Pale sage at 30% opacity leaves geography readable, with labels, route guidance, markers and attribution above it. A nearby view is capped at 4096 cells, or 1024 in low detail; wide/horizon views show a zoom/Overview prompt and defer fog. The displayed percentage applies only to the visible grid.

Layers has one visibility toggle. Area discovery expands below the map for session counts, recording choice, deletion and retries. Manual preview and unsaved device observations remain separate in-memory sets. They never upload cell IDs or become saved device observations. Saved and session areas may overlap; the UI says so. The 2D geographic fallback preserves the same preview and saved state after graphics loss.

Saving requires `FOOD_GO_EXPLORATION_ENABLED=true`, the existing verified-account gates and explicit opt-in for each mounted Explore session. The flag is documented with default false; production account/provider gates were not enabled. Loading saved account settings never resumes uploads. The checkbox represents requested intent so a pending opt-in can be cancelled. Recording begins only after server acknowledgement and a newer raw GPS timestamp. Precise fixes exist only in mounted state, one current retry envelope and the in-flight POST; they are never put in localStorage, URLs, application logs or the saved database columns. Hidden, off, unmount, account change and clear invalidate pending callbacks and buffers. A lost remote opt-out/deletion remains visibly unconfirmed and can be retried; aborting a browser request cannot undo a server transaction already accepted.

The server requires the existing active, verified, non-banned session. It derives cells and accepts no user ID, client-selected cell, XP or reward authority. Each explicit recording grant issues a new UUID; observations must match it. Clear and opt-out remove that active ID, so a delayed request from an earlier session cannot restore cleared areas, including with tolerated device clock skew. Freshness is also checked against the latest consent time, 15-second age, three-second future limit and last accepted timestamp. Accuracy worse than 35 metres and coarse implausible travel are rejected. A five-minute gap permits a new coarse anchor without claiming travel. Per-account advisory locking, five-second attempt spacing, 1000 attempts per Sydney day, request hashing/idempotency and 4096 saved-cell capacity bound writes. The client uses six-second pacing, one stable retry UUID and 15-second expiry with no location backlog.

The three private tables contain coarse cells, consent/observation times, hashed short-lived request receipts and abuse counters. They enable RLS, deny direct client access and expose only a checked private definer behind a public invoker wrapper. Clear removes cells, receipts, consent and the last coarse anchor, while retaining minimal counters so repeated deletion cannot reset quotas. Receipts older than two days are removed lazily on later observations, not by a scheduled job. Account deletion cascades the records. All state explicitly reports `rewardEligible:false`. These checks are unverified browser device assertions, not spoof-proof arrival, physical visits, check-ins, geographic reward milestones or eligibility for offers/XP/quests.
